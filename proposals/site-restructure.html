Proposal · draft for review

Restructuring VashonSoftware.com: four service pages, one About & Contact, calmer headings

The Services page now holds six different stories on one long scroll. This splits it into four pages, each aimed at one kind of client. It folds About and Contact into a single page and tones down the headings. It also sketches three overall style directions to aim for later.

Prepared 11 Nov 2026Repo: D:\Projects\VashonSoftware.com\VashonSoftware.comNothing changed on the site yet

Recommendations

  1. Four top-level service pages: Websites, Software, Emergency Tech, Consulting. Only Websites gets subpages now, because it is the only area with enough content. /services stays as a short hub so old links keep working.
  2. One "About & Contact" page at /about, with the form at the top right. /contact redirects to /about#contact. The nav loses two links and keeps the "Contact John" button.
  3. Fix headings first, separately from any restyle. Move every heading's size into two shared components and drop the 120% root font size. After that, a full restyle is a change to one file plus the tokens.
  4. Style direction to aim for: start with A (refined current look). Choose between B and C later, once the new pages exist and there is real content to judge them on.

4 · About & Contact

Shrinking About and Contact

A. Merge into one page at /about

Recommended

Two columns. Left: a short bio and photo, then the credentials as a compact list. Right, sticky on desktop: phone, email, "what to expect" and the form (id="contact"). The header button goes to /about#contact. Each service page ends with the same small "Talk to John" block, so most visitors never need the page at all.

ForOne page instead of two. The people who want to know who John is are mostly the same people about to get in touch.
AgainstNeeds a redirect for /contact (one line in public/_redirects), and existing email signatures pointing at /contact go through it.

B. Keep both, drop both from the nav

No merge; About and Contact move to the footer, the button still goes to /contact. Least work, but the pages stay as thin as they are now.

C. Merge into /contact as "Work with John"

Same as A, but the form leads and the bio follows. Better if most traffic is ready to get in touch; worse for recruiters who search for "about".

5 · Headings

Why the headings feel dramatic, and three calmer options

Three things stack up. The root font size is 120% (globals.css:100), so every rem is 19.2px. Page titles use text-4xl md:text-5xl lg:text-6xl, which comes out at 72px on a laptop. And they are set in Montserrat Bold, a wide display face, with 80–112px of padding above. Each page also writes its own sizes inline, so there is no single place to change them.

Every specimen below shows the same /websites header at real pixel size.

Do this part regardless of which option wins

Add two small components, PageHeader.astro (eyebrow or breadcrumb, h1, lead) and SectionHeader.astro (h2, optional subtitle), and replace the inline sizes on every page. Set the sizes once in globals.css:

html { font-size: 106.25%; }            /* 17px, was 120% = 19.2px */

@layer components {
  .page-title    { font-size: clamp(2rem, 1.6rem + 1.4vw, 2.5rem);
                   font-weight: 600; line-height: 1.15; letter-spacing: -0.015em; }
  .section-title { font-size: 1.5rem; font-weight: 600; letter-spacing: -0.01em; }
  .eyebrow       { font-size: .8rem; letter-spacing: .08em; text-transform: uppercase; }
}
/* hero padding: py-12 md:py-16 instead of py-20 md:py-28 */

Changing the root size shrinks everything by about 11%, including body text and spacing. That's probably welcome, but the pages need a look afterwards. A safer first step is to keep 120% and change only the heading sizes.

7 · Order of work

Suggested phases

Each phase can ship on its own, and the site stays consistent in between.

Phase 1 · S

Heading components and calmer sizes

Add PageHeader and SectionHeader, switch every page to them, apply heading option 1. Check PageSpeed (layout shift) and both themes.

Phase 2 · M

Four service pages

Create /software, /emergency, /consulting. Turn /services into a short hub that keeps the old anchor ids (#health-it, #websites…) on its cards. Update the nav, footer and Home's feature tiles (three → four).

Phase 3 · M

Websites subpages

Split websites.astro into overview plus /included, /care-plans, /compare. Add a small in-page nav strip shared by the four Websites pages. Fit quiz stays on the overview.

Phase 4 · S

About & Contact merge

Shared ContactForm component; merged /about; /contact /about#contact 301 in public/_redirects; "Talk to John" block at the end of each service page.

Phase 5 · L

Full restyle (later)

Pick a direction from section 6 and build it as tokens in globals.css plus the two header components. If Phase 1 is done, this touches few page files.

S / M / L is relative size, one evening to a few sessions. Redirects: hash fragments can't be redirected server-side, which is why /services stays as a hub instead of a redirect. Sitemap and RSS regenerate on build.
